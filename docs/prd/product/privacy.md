# 데이터 경계

상태: 인터뷰 R9까지 반영, 화면 배치는 프로토타입 세션에서 확정

근거: [결정 로그](../decisions.md) D-R0-02, D-R0-03, D-R2-05, D-R2-09, D-R2-11, D-R3-04, D-R3-11, D-R4-02~11, D-R6-01~05, D-R7-01~03. [research §6.3·7.3·8.2·9](../../../street-fitting-research.md#63-마스킹-후-생성형-피팅)은 보관·모델 정책의 근거다. 구체적 전송 형식과 삭제 연쇄는 [relay-api](../contracts/relay-api.md), [data-model](../contracts/data-model.md), [device-modules](../contracts/device-modules.md)를 따른다.
R9 추가 근거: D-R9-01(자동 수치 판정), D-R9-02(바로 자른 가게 옷의 Spark 전송), D-R9-03(결과 스냅샷), D-R9-04(Trip 통합).

## 본인 사진

- `SelfPhoto`는 한 장이며 촬영 또는 갤러리에서 새 사진을 고르면 이전 사진을 대체한다. 원본 `file`과 얼굴·머리 영역 `headMask`는 기기 안에만 둔다(D-R4-02).
- 사진 중심점으로 EdgeTAM 사람 마스크를 얻고 윤곽 위쪽에서 폭이 가장 좁은 목 지점 위를 머리로 본다. 사용자 입력·수동 영역 조정·전송본 확인 화면 없이 코드가 `maskedFile`을 만든다. 이 방법의 정확도는 미확인이다(D-R4-03, D-R7-01).
- 얼굴·머리 영역을 찾지 못하면 등록을 성공 처리하지 않고 다시 촬영하게 한다. 어떤 실패 경로에서도 원본을 대체 입력으로 전송하지 않는다(D-R4-11).
- Muse Image 요청은 마스킹된 본인 사진 1장, 가게 대상 1벌, 함께 입을 옷 0~5벌이다. 결과의 목·어깨 경계 색 차이와 어긋남을 자동 수치로 판정해 PoC 임계값 안일 때만 기기에서 얼굴을 붙인다. 기준 밖이면 자동으로 얼굴 없는 결과를 만들고 `Result.faceless`에 남긴다(D-R4-07, D-R9-01).
- 마스킹은 완전한 익명화를 뜻하지 않는다. 몸·배경·문신 등 식별 단서가 남을 수 있다. Meta의 즉시 삭제나 무보관을 보장하지 않는다(D-R0-02; research §6.3).

## 데이터 경계

"기기에 저장"과 "절대 전송하지 않음"을 구분한다. 쇼핑 사진 원본은 로컬에 보관하지만 선택된 최대 3장은 SAM으로 전송할 수 있다. 가게 옷/옷장 조각도 로컬에 보관하면서 아래 목적별로 전송한다(D-R3-01, D-R4-06, D-R4-07).

- 촬영 사진은 갤러리에 자동 저장하지 않는다. 사용자가 사진별 내려받기를 선택하면 EXIF GPS를 제거한 복사본만 갤러리에 저장한다. 앱 원본의 위치와 `Piece.walkTo`는 바꾸지 않는다. 가져오기는 옷장·본인 사진에만 허용한다(D-R2-05, D-R2-09, D-R2-11, D-R4-02).
- 피팅 결과 내려받기는 기본 OFF 기능 플래그다. 통합에서 Muse Image 워터마크·메타데이터 보존을 확인한 뒤에만 활성화한다. 내려받기 시 GPS 제거와 provenance 보존을 동시에 만족해야 하며, 충돌 시 플래그를 켜지 않는다(D-R2-11, D-R4-10).
- 옷 사진에 담긴 다른 사람은 MVP에서 따로 가리지 않는다. "본인 사진의 얼굴·머리 제외"를 모든 쇼핑 사진 속 인물에 대한 보장으로 확대하지 않는다(D-R0-02; research §9).

## 보관·삭제·오프라인

- 쇼핑 모드 종료는 `Trip.status='ended'`와 `endedAt`을 기록하고 해당 trip의 `TrailPoint`를 모두 지운다. `Shop`, `Photo`, 메모와 사진 위치는 남는다(D-R0-03, D-R3-03).
- trip 삭제는 그 trip의 `Shop`, `Photo`, `PhotoEmbedding`, `TrailPoint`를 삭제한다. 저장한 `Piece`는 잘라낸 이미지와 `walkTo`를 유지하고 `photoId`, `shopId`, `tripId`를 null로 만든다. "Original photo"만 사라지고 길 안내·피팅은 유지한다(D-R3-11, D-R5-01).
- 사진 하나 삭제는 해당 파일·`Photo`·`PhotoEmbedding`을 지우고 연결된 원본 열기를 끊는다. 저장한 조각을 함께 지우는 동작으로 바꾸지 않는다. 저장한 옷·옷장 옷·결과 삭제는 각각 별도 제공한다. 세부 참조 정리는 [data-model](../contracts/data-model.md)을 따른다(D-R3-11).
- 대상 Piece를 삭제해도 Result의 옷 이름·잘라낸 이미지·길 안내 위치 복사본은 남고 결과 보기·길 안내는 유지한다. 대상이 없으면 "Change pieces"를 비활성화한다. 결과를 삭제할 때 그 결과 소유 복사본도 정리하며 원래 Piece와 삭제 수명을 분리한다(D-R9-03).
- 오프라인 외관 묘사·옷 이름 작업(옷장 및 trip에서 바로 자른 가게 옷)은 로컬 `QueueJob`에 보관하고 재연결 후 처리한다. 삭제된 작업 원본을 대기열이 다시 전송하지 않게 정리한다 [추론]. 검색·피팅·음성·길 안내는 오프라인 작업 대기열에 넣지 않고 연결 안내 후 사용자가 재시도한다(D-R3-11, D-R6-03, D-R9-02).

## 릴레이와 로그

- 릴레이는 로컬 Mac에서만 실행하는 FastAPI 목적별 stateless API다. API 키·고정 시스템 프롬프트·도구 스키마는 릴레이에만 있다. 쿼터·비용 상한 및 Firestore 원장이 없다(D-R1-02, D-R6-02, D-R6-05, D-R7-02).
- 요청 이미지·음성·좌표를 DB, 파일, 로그에 남기지 않고 요청 처리 메모리에서만 전달한다. 기본 로그 허용 목록은 엔드포인트, 가명 ID, 지연, 상태 코드, Spark 턴 수다. 요청/응답 본문이나 에러 덤프를 통째로 기록하지 않는다(D-R6-04; research §7.3).
- 로컬 개발 플래그가 켜진 경우에만 질의 텍스트와 Spark 응답 본문을 기록할 수 있다. 이미지·음성·좌표는 이 예외에도 금지다. 질의·응답에 좌표가 섞인 경우에도 로그에 남지 않게 제외한다 [추론]. 메모·음성 원문·업로드 바이트를 일반 디버그 로그로 허용하는 예외가 아니다(D-R6-04).
- 지원되는 Meta 요청에 `store:false`를 쓰고 Files API 대신 요청 내 이미지 바이트를 사용한다. 외부 검색·셸 도구를 열지 않는다. 이 설정은 릴레이 무저장과 별개이며 Meta의 서비스/안전 목적 보관까지 없애지 못한다(D-R1-02, D-R0-02; research §6.3·7.3).
- Privacy 화면은 "모든 데이터가 기기에만 있다" 또는 "서버는 아무것도 보관하지 않는다"고 포괄 보장하지 않는다. 새 데이터 목록·로컬 개발 예외·외부 제공자 경계의 최종 영어 문구는 프로토타입 세션에서 확정한다(D-R6-04, D-R7-08).

## 불변식(테스트 대상)

1. 마스킹되지 않은 본인 사진 바이트와 얼굴·머리 마스크 원본은 어떤 HTTP 요청에도 실리지 않는다(D-R0-02, D-R4-11).
2. `FaceMask` 실패 시 `/v1/tryon` 요청 수는 0이고, 원본 본인 사진으로 우회하지 않는다(D-R4-11, D-R7-01).
3. `/v1/tryon`은 마스킹된 본인 사진 1장과 옷 최대 6장만 받으며 옷장 옷을 대상으로 한 요청은 거절한다(D-R4-07, D-R4-09).
4. trip 종료 후 해당 trip의 `TrailPoint`는 0건이고, 가게·사진 위치는 남는다(D-R0-03, D-R3-03).
5. trip 삭제 후 관련 Shop·Photo·PhotoEmbedding·TrailPoint는 0건이며, 저장한 Piece의 조각·`walkTo`는 같고 `photoId/shopId/tripId`는 null이다(D-R3-11).
6. 사진 삭제 후 해당 사진·임베딩·파일과 "Original photo" 연결을 사용할 수 없고 삭제한 사진의 대기 작업도 실행되지 않는다(D-R3-11, D-R6-03; 대기 작업 정리는 [추론]).
7. 방문 요약 요청에는 가게 메모가 포함되고 원본 좌표·이미지·사진 임베딩은 포함되지 않는다(D-R1-02, D-R3-04).
8. 옷장 및 검색 없이 trip에서 바로 자른 가게 옷의 이름 붙이기는 조각 이미지만 Spark로 보내고 옷장 원본·trip 원본 사진을 보내지 않는다. 바로 자른 가게 옷은 오프라인에서 `label_piece`로 대기하고 "Picked item"으로 표시된다(D-R4-06, D-R9-02).
9. 같은 질의의 5번째 Spark 호출과 누적 4번째 SAM 사진은 릴레이에서 차단한다(D-R3-01).
10. 음성 요청의 WAV 길이는 15초 이하다. Find it 외 화면에는 녹음 시작 마이크가 없다(D-R3-07, D-R7-09).
11. 갤러리에 내려받은 모든 사진에는 EXIF GPS가 없고 앱 원본의 위치는 변하지 않는다. 결과 내려받기 플래그 OFF에서는 결과 파일이 갤러리에 생성되지 않는다(D-R2-11, D-R4-10).
