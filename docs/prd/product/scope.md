# 제품 범위와 규칙

상태: 인터뷰 R9까지 반영, 화면 배치는 프로토타입 세션에서 확정

근거: [인터뷰 결정 R0~R9](../decisions.md). [research §9–10](../../../street-fitting-research.md#9-최종-mvp-범위-11월-3일-확정)은 근거 자료이며, 충돌하면 인터뷰 결정이 우선한다. 이 계층 문서는 슬라이스가 링크한 상위 문서만 읽어도 구현할 수 있게 구성한다(D-R0-01).

## 전제와 구현 경계

- Android 스마트폰에서 사진만 촬영한다. 영상·실제 글래스·DAT Mock 캡처는 제외한다. UI, 질의, 음성 전사, 외관 설명은 영어다(D-R0-02, D-R2-06).
- Meta 제공 모델만 쓴다. 릴레이 API는 Muse Spark 1.3 Standard, SAM 3.1, Muse Image, Muse Voice Transcribe다. 기기 ONNX는 EdgeTAM과 PE-Core-T16 이미지 타워, 릴레이는 PE-Core 텍스트 타워를 실행한다. PE-Core는 사진 검색용이며 옷 후보 제거 필터가 아니다(D-R0-02, D-R3-02; research §7.1).
- 본인 원본은 기기에만 둔다. 코드가 얼굴·머리를 자동 마스킹한 사진만 전송하고, 사용자 확인 화면이나 수동 마스킹은 없다. 마스킹 합격은 사람이 표시한 머리 영역과 비교해 모든 본인 fixture 전송본의 얼굴·머리 픽셀이 0이며, 사람 없는 사진은 반드시 실패하는 조건이다. 재합성은 목·어깨 경계의 색 차이와 어긋남을 자동 수치로 판정하고, PoC에서 정할 임계값 안일 때만 얼굴을 붙인다. 넘으면 해당 결과를 자동으로 얼굴 없는 결과로 만든다. 합격 여부와 임계값 실측은 미확인이다(D-R4-03, D-R4-04, D-R4-11, D-R7-01, D-R9-01). 상세: [데이터 경계](privacy.md).
- `app/`은 Capacitor 8 + React 19다. UI는 React, 네이티브 카메라·위치 포그라운드 서비스/알림·ONNX·마스킹/재합성은 자체 Capacitor Java 플러그인이다. 지도는 WebView의 MapLibre GL JS다(D-R7-03).
- `relay/`는 로컬 Mac의 Python + FastAPI다. code-first로 `relay/app/schemas.py`와 FastAPI 라우트에서 내보낸 **`relay/openapi.json`**이 계약 원본이며, `openapi-typescript`로 앱 **`app/src/generated/relay-api.d.ts`**를 생성한다. S00은 전체 스키마와 501 스텁 라우트를 먼저 만들고 각 구현 슬라이스가 실제 동작으로 교체한다. `relay/openapi.yaml`, `datamodel-code-generator`, `app/src/relay/types.ts`는 쓰지 않는다. Cloud Run과 Firestore도 쓰지 않는다(D-R6-02, D-R6-05, D-R7-02; [relay-api §8](../contracts/relay-api.md)).
- 앱이 에이전트 루프와 도구를 실행한다. 릴레이는 목적별 stateless 엔드포인트만 열고 시스템 프롬프트·도구 스키마를 고정한다. 범용 프록시가 아니다(D-R1-02).
- Firebase 익명 인증과 App Check를 쓰고, 에뮬레이터는 개발용 프로젝트/debug provider를 쓴다. 익명 UID 기반 가명 ID를 Meta `safety_identifier`로 보낸다. 화면에는 dev 표시가 없다(D-R6-01, D-R7-07).
- UI는 기존 흐름·문구를 유지하되 R2~R9로 바뀐 기능이 우선한다. Astryx로 시각 표현을 근사한다. 새 배치·문구는 프로토타입 세션에서 확정한다(D-R1-03 및 각 후속 결정).

## 확정된 한도와 상태

- 검색 한 질의당 Spark 최대 **4회**, SAM 전송 사진 합계 최대 **3장**이다. 릴레이가 질의 단위로 강제한다. 사용자/팀 쿼터와 별개인 기능 규칙이다(D-R0-05 → D-R1-02, D-R3-01, D-R6-02).
- SAM 후보는 점수 순 **상위 3개**를 먼저 보여 주고 "Show all"로 나머지를 펼친다. EdgeTAM은 탭당 마스크 3개와 점수를 준다. 후보를 PE-Core나 별도 임계값으로 제거하지 않는다(D-R0-05 → D-R3-02).
- 피팅은 본인 **1장 + 대상 1벌 + 함께 입을 옷 0~5벌 = 이미지 최대 7장(1+6)**이다. 옷장 옷만으로 시작할 수 없다(D-R4-07, D-R4-09).
- 오프라인에도 촬영·기록·로컬 탐색·옷장·저장은 가능하다. 외관 묘사와 옷 이름 붙이기(옷장 및 trip에서 바로 자른 가게 옷)를 `QueueJob`에 넣어 재연결 후 처리한다. 검색·피팅·음성·길 안내는 연결 없음을 알리고 재시도하게 하며 자동 대기열에 넣지 않는다. 실패·빈 상태의 새 문구는 프로토타입 세션에서 확정한다(D-R6-03, D-R9-02).
- 릴레이는 본문을 지속 저장하지 않는다. 기본 로그는 엔드포인트·가명 ID·지연·상태 코드·Spark 턴 수뿐이다. 로컬 개발 플래그로만 질의와 Spark 응답 본문을 추가할 수 있으며 이미지·음성·좌표는 항상 금지다(D-R6-04).

## 구현·검증과 배포 선행 조건

- PRD는 UI뿐 아니라 릴레이, ML, 위치·가게, 도구 실행, 마스킹/재합성, 길 안내 전체를 다룬다. S01~S11을 Orca로 분배하며 [relay-api](../contracts/relay-api.md), [agent-tools](../contracts/agent-tools.md), [device-modules](../contracts/device-modules.md), [data-model](../contracts/data-model.md) 공유 계약을 먼저 고정한다(D-R1-01, D-R7-04, D-R7-05).
- 구현 소유권은 공유 계약과 슬라이스 배분을 따른다. S06은 `app/src/data/**`, 네이티브 Store와 `app/src/native/store.ts`, 오프라인 대기열 저장·재시도·worker·`describe_storefront`/`label_piece` handler를 맡는다. S05는 FaceMask 네이티브 알고리즘·판정, S10은 피팅 JS 오케스트레이션, S07은 에이전트 루프만 맡으며 대기열 worker는 맡지 않는다(D-R7-04).
- 단위 작업은 에뮬레이터·fixture·Meta API mock으로 검증한다. 실제 Meta API는 통합 단계에만 쓴다. 에뮬레이터에서 전체 흐름을 mock 한 번, live 한 번 수행하며 실기기 시연은 하지 않는다(D-R1-04, D-R7-05).
- 릴레이 접속은 에뮬레이터에서 `http://10.0.2.2:<port>`다. R6의 실기기 터널은 R7에서 필수가 아니게 됐다(D-R6-05, D-R7-05).
- 매장·외관·옷장·본인 시연 이미지는 Codex 이미지 생성으로 만든다. debug 캡처 소스는 adb로 넣은 폴더를 셔터마다 순서대로 읽고 adb intent extra로 켠다. 화면 표시가 없고 release 빌드에는 포함하지 않는다(D-R7-06, D-R7-10).
- 음성 E2E는 debug 전용 WAV fixture를 사용한다. intent extra `sf_voice_source=fixture|mic`, `sf_voice_fixture_dir`로 선택하고 `start()`마다 실시간 WAV → 실제 VAD → silence 종료 → `completed` 1회 경로를 실행한다. 호스트 마이크·사람 발화는 필수 합격 기준이 아니다. release 제외·화면 표시 없음은 카메라 fixture와 같다(D-R3-07, D-R7-10 원칙을 확장한 통합 구현 결정; [device-modules §8 Voice](../contracts/device-modules.md)).
- 슬라이스 배포 전 커밋, 모델 파일 복사, Orca setup 훅 설정이 필요하다. 이 작업은 사용자가 직접 하거나 따로 지시한다. 문서를 근거로 임의 실행하지 않는다(D-R7-11).
- 해커톤 제출물은 필수 양식의 **3분 데모 영상과 public GitHub 저장소**다. 배포는 하지 않으며 GitHub Releases를 포함한 APK 공개와 클라우드 릴레이를 모두 제외한다. 영상은 로컬 Mac 릴레이에 연결한 에뮬레이터에서 **실제 API**로 녹화한다(D-R8-01).
- 문제 주제는 **Build for Your World**, 참가 트랙은 팀원 없는 개인 **Indie Developer**다(D-R8-02, D-R8-03).
- 후속 확인은 운영 정책 확장보다 실제 기능 동작에 집중한다. 자동 마스킹·재합성, Meta 응답 품질/지연, 결과 provenance 보존은 통합 단계의 미확인 항목이다(D-R6-06, D-R4-10, D-R7-01).
