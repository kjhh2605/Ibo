# 고조회수 짧은 데모 영상 6편 심층 분석 + 길찾기 영상 보조 분석

관측일: **2026-11-04**. Street Fitting 영상의 구조·화면 연출만 연구했으며 저장소/앱 UI는 보지 않았다. 제품·개인정보 처리 요구사항은 이번 작업의 최신 브리프를 따른다.

## 근거와 한계

- YouTube 검색(`hackathon demo`, `hackathon submission`, `Pennapps demo`, `HackMIT demo`, `hackathon winner`, `Google shopping try on`, `Project Astra`, `Google Maps Live View`)과 조회수 정렬 검색을 함께 사용했다. 검색 결과의 관련 없는 강좌·브이로그·행사 전체 중계를 제외했다.
- **YouTube/X 전체의 절대 조회수 1위라는 주장은 할 수 없다.** 여기서 해커톤 2편은 조사한 검색 표본 안에서 높은 조회수를 가진 1–4분 실제 제출물이다. `2025 Global AI Hackathon Presentations`는 검색상 1,247,432회이나 87분 중계라 제외. `Hackathon Winners Q1 2023`는 검색상 722,648회·3:58이지만 개별 제품 데모가 아닌 수상작 소개라 제외. 조회수는 영상 구조가 우수하다는 인과 증거도 아니다.
- 6편 모두 `yt-dlp` 메타데이터·영어 VTT 자막·다운로드 영상의 샘플 프레임을 직접 확인했다. 기본 8초 간격, 쇼핑 영상은 2초 간격, Astra는 도입/전환 추가 샘플. 문장 시작 시간은 자막 기반, 화면 전환 경계는 샘플 사이이므로 약 ±2–8초의 구간화다. 프레임만으로 정확한 트랜지션 프레임 수나 연속 테이크 진위를 단정하지 않는다.
- 음성의 내용은 자막으로 확인. **음악의 장르·볼륨·비트 동기화는 직접 청음하지 않았으므로 확인하지 않았다.** 자막의 `[Music]`만 음악 존재 근거로 쓴다. 음성 합성 여부도 추정하지 않는다.
- 영어 자동자막은 고유명사 오류가 있다(`Pi`→`pie`, `Piclub`→`high club` 등). 화면에 있는 표기로 바로잡되 정확 인용은 짧게만 사용했다.
- 원자료: `/tmp/vidref/<YouTube ID>.info.json`, `.mp4`, `.en.vtt`; 기본 콘택트 시트 `-timed.jpg`, 추가 `-detail.jpg`. 마지막 보조 길찾기 영상은 자막 다운로드가 HTTP 429로 실패했으므로 6편 심층 분석에 포함하지 않는다.

### 화면·효과·증거

- **세로 폰을 16:9에 억지로 확대하지 않고 실제 주변 공간 안에 넣는다.** 시청자는 폰이 보는 물체와 폰 화면을 동시에 확인한다. 공간을 이동하는 것 자체가 장면 변화여서 삽입 그래픽이 적다.
- 하단의 작은 검정 배경 자막이 화자/답변을 받친다. 복잡한 타이포/모델 배지/기술 다이어그램 오버레이 없이 실제 질문과 답이 전부다.
- 처음 ‘single take, real time’이라고 **영상 자체가 주장한다**. 샘플 프레임으로 편집 부재를 독립 검증한 것은 아니다. 속도 표시나 가속 표시는 관찰되지 않는다.
- 기술적 깊이는 ‘객체→세부→코드→장소→과거의 물체 기억’이라는 점진적 능력 변화로 보여 준다. 내부 파이프라인 설명은 없다.
- 음성 내용 확인, 음악 구성 미확인. 현장 대화형 구조가 중심이라는 것은 자막과 화면의 일치로 확인 가능.

### 가져올 것 / 피할 것

- **가져올 것 1:** 첫 고지는 신뢰 형성의 일부. 우리의 필수 ‘pre-existing vs built during hackathon’ 문장도 4–5초 안에 선명하게 끝낸다.

## 종합: 반복되는 구조와 Street Fitting의 3분 권장안

### 관측에서 얻은 패턴

1. **높은 조회수 ≠ 좋은 제출 구조.** TELTLK/Piclub은 실제 고조회수지만 첫 사용까지 30/89초 걸리고 작은 폰·기능 반복이 약점. 조회수만으로 따라 하면 안 된다.
2. 강한 제품 데모는 첫 10초에 **질문/과제**를 던진다. Be My Eyes는 0초 질문, Astra 2025는 7초 안에 고칠 대상, Google Shopping은 5초 안에 대비 질문.
3. 성공적인 AI 표현은 모델 이름 나열이 아니라 **입력→눈으로 검증 가능한 출력→사용자의 다음 행동**이다. 안경 기억→안경 회수, 택시 인식→탑승, 피팅→친구와 결정.
4. 폰을 가로 화면에 놓는 좋은 방법은 두 가지: **Astra처럼 실제 공간 안의 손+폰**, **Google Shopping처럼 현실/인물과 확대 UI의 분할**. 중앙에 작은 폰+정적인 빈 여백만 남기는 방식은 피한다.
5. 빠른 컷이 곧 빠른 데모는 아니다. 핵심 결과는 읽을 시간을 남기고, 불필요한 로그인/스크롤/반복은 줄인다. 가속은 Astra 2025처럼 표시한다.
6. 기술 설명을 완전히 생략한 브랜드 광고를 그대로 따라 하지 않는다. 우리는 Impact뿐 아니라 Meta AI와 execution을 입증해야 하므로 **행동 위의 짧은 모델 라벨 + 마지막 18초의 파이프라인/프라이버시 증거**를 추가한다[추론].
