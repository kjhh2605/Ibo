# 제출 영상 기획안 (v2: 서비스 소개형 구조)

상태: 레퍼런스 조사를 바탕으로 서비스 소개형 구조안을 작성했다. 고지는 마지막으로 옮겼다. 촬영 소재(현장 촬영 여부)를 확정한 뒤 구간별 화면 구성·전환·효과·내레이션을 쓴다.
범위: 영상 기획만 다룬다. 앱 UI/UX는 바뀔 예정이므로 화면 문구·버튼 이름·화면 배치를 기획에 넣지 않는다. 앱 화면은 기능 단위("검색 결과", "피팅 결과")로만 부른다.

## 확정 사항

- 톤: **서비스 소개 영상**. 제품 출시 영상처럼 짧은 문장, 현재형, 사용자("you") 시점으로 말한다. 동묘 이야기는 도입 훅으로 압축하고, 개발 과정·제작담은 넣지 않는다.
- 내레이션: 본인 영어 음성 + 영어 자막.
- 고지 위치: **마지막 엔드카드**. 내용은 Astryx 디자인 시스템, Capacitor 템플릿, vendored stageshow UI kit(MIT, 프로토타입 전용), Meta 공개 가중치 EdgeTAM·PE-Core가 기존 자산이고 나머지는 이번 주 작업이라는 것. 화면 텍스트와 내레이션 모두 두 범주를 한 문장 안에서 함께 말한다. "Everything was built this week"처럼 전부 새로 만들었다고 읽히는 표현은 쓰지 않는다(R2).
- 검색 데모: 음성 질의.
- 피팅 인물: Codex로 생성한 데모 인물(D-R7-06). 화면에 "AI-generated demo person"을 표시한다.
- 배경 사례: 서울 동묘 구제시장.

## 문제 정의

**한 문장:** 동묘 같은 길거리 구제시장의 옷은 하나뿐인데, 그 옷을 다시 찾고, 내 옷이나 다른 가게 옷과 맞춰 입어 보고, 내 사진을 지키면서 결정할 도구가 없다.

| # | 문제 | 왜 기존 도구로 안 되는가 | Street Fitting의 답 | Meta 모델 |
| --- | --- | --- | --- | --- |
| P1 | 다시 찾아갈 수 없다 | 바닥에 펼쳐 놓은 노점은 이름도 간판도 없고 지도에 없다 | 사진마다 찍은 위치를 남기고, 그 자리까지 걸어서 안내 | — |
| P2 | 어떤 사진이었는지 못 찾는다 | 수십 장 중 그 옷이 찍힌 사진을 기억에 의존해 뒤진다 | 말로 묻으면 사진과 가게 묘사를 함께 검색 | Voice Transcribe, Muse Spark 1.3, PE-Core |
| P3 | 가상 피팅이 시장에서는 안 된다 | 기존 피팅은 쇼핑몰의 상품 이미지가 있어야 한다. 시장 옷에는 상품 이미지가 없다 | 내가 찍은 사진에서 옷만 잘라 피팅 재료로 사용 | SAM 3.1, EdgeTAM |
| P4 | 다른 가게 옷끼리, 내 옷과 맞춰 볼 수 없다 | 옷이 서로 다른 노점에 있고, 내 옷장은 집에 있다 | 대상 1벌 + 내 옷장·다른 가게 옷 최대 5벌을 함께 입혀 봄 | Muse Image |
| P5 | 상상과 실제로 보는 것은 다르다 | 하나뿐인 옷이라 나중에 사려 하면 이미 없을 수 있다. 결정이 급하다 | 내 몸에 입힌 결과를 보고 결정 | Muse Image |
| P6 | 내 사진이 유출될까 걱정된다 | 피팅 서비스에 얼굴이 담긴 원본을 올려야 한다 | 본인 사진은 얼굴·머리를 기기에서 지운 것만 전송하고, 얼굴은 기기에서 다시 합성한다. 쇼핑 사진·외관·잘라낸 옷은 검색·피팅을 위해 릴레이를 거쳐 Meta API로 간다 | 기기 마스킹(EdgeTAM 기반) |

수혜자: 구제·빈티지 쇼핑객, 그리고 지도에 없는 노점·시장에서 옷을 사는 사람 [추론: 동묘 외 다른 국가의 벼룩시장에도 같은 문제가 있다고 가정].

세 조사가 공통으로 가리킨 원칙:

1. **옷 한 벌로 끝까지 간다.** 동묘에서 본 재킷 한 벌을 촬영 → 음성 검색 → 피팅 → 그 노점 복귀로 추적한다. 기능별 독립 예시로 쪼개지 않는다.
2. **첫 실제 동작을 0:24 안에 시작한다.** 초안의 0:35는 늦다. 고조회수 해커톤 영상(TELTLK 0:30, Piclub 1:29)도 이 점이 약점이었다.
3. **모델 이름은 행동에 붙인다.** 모델 로고 나열 대신 입력 → AI 산출물 → 사용자의 다음 행동을 같은 장면에 둔다.
4. **기술 구간은 한 화면, 20초 안팎.** PHONE / META API 경계 위에 방금 본 실제 산출물(질의, 후보, 마스킹 이미지, 결과)을 재사용한다. 별도 슬라이드 덱이나 코드 스크롤은 쓰지 않는다.
5. **대기 시간은 줄이되 밝힌다.** 반복 대기만 자르고 "Wait shortened · actual 28s"처럼 해당 실행의 측정값을 표시한다(28초는 예시). 전체 배속이나 음성 배속은 하지 않는다. 음성 질의 → 후보 표시 한 구간은 원속도로 남긴다.
6. **결말은 앱 밖에서 맺는다.** 지도만 띄우고 끝내지 않고, 그 노점과 그 옷에 다시 도착하는 장면으로 닫는다.
7. **16:9 화면에 작은 폰을 가운데 두고 여백을 비워 두지 않는다.** 현장·인물과 확대한 앱 화면을 나누거나, 손에 든 폰을 현장 안에서 촬영한다.
8. **개인정보 표현은 정확하게.** "Face and hair are masked on-device before upload; the face is restored on the phone." 수준으로 말하고 화면으로 보여 준다. "Everything runs on-device", "No photos leave your phone"은 쓰지 않는다.
9. **소리:** 배경음은 약하게, 음성 질의 중에는 줄이거나 끈다. 효과음은 주요 전환·결과 1~2곳만 [추론].

### 증거 층 분리

제품 동작의 증거는 **에뮬레이터 화면 녹화**뿐이다. 실제 API를 쓰고, GPS는 주입하며, 카메라는 debug fixture다(D-R8-01, D-R7-05, D-R7-10). 현장 영상을 쓰더라도 이야기와 맥락을 위한 B-roll로만 쓴다.

| 층 | 소재 | 쓰는 곳 | 표시 |
| --- | --- | --- | --- |
| 앱 동작 | 에뮬레이터 화면 녹화 | ①~④, 작동 원리 | 처음 등장할 때 "Real app recording · Android emulator · live Meta APIs" |
| 현장 맥락 | 동묘 B-roll (촬영 시) | 훅, 촬영 전후, 복귀 결말, 마무리 | "Dongmyo market footage" |
| 생성 소재 | Codex 생성 데모 인물 | ③ | "AI-generated demo person" |

- 현장 B-roll 속 휴대전화가 앱을 실행하거나 길 안내로 노점에 도착한 것처럼 보이게 편집하지 않는다. 복귀 결말은 "에뮬레이터 경로 화면 → (B-roll) 같은 노점" 순서로 붙이고, 두 화면 사이에 층 표시가 바뀌게 한다.
- 앱 화면과 B-roll을 같은 프레임에 나란히 둘 때도 각 영역에 층 표시를 붙인다.
